# نموذج — تعبئة نماذج أوامر العمل

واجهة HTML عربية تعمل مع خادم Python. إدخال أمر واحد أو استيراد Excel/CSV/جدول ملصق، أسئلة للبيانات الناقصة، حفظ تلقائي، معاينة PDF وتصدير مجموعة أوامر ZIP. تولّد النسخ المعبأة فوق خلفيات PDF الأصلية بخط Haya؛ أسماء وتوقيعات النسخ الأصلية تبقى كما هي.

مستودع GitHub للكود فقط. ملفات PDF الخاصة، قاعدة البيانات والأوامر ليست منشورة فيه. تحتاج نسخة جديدة مستنسخة من GitHub إلى نسخ مجلد `app/assets/templates` من حزمة التشغيل الخاصة بالمستخدم.

## تشغيل سريع

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m app.server
```

افتح http://localhost:8080. تحفظ البيانات تلقائيًا في `.data/orders.sqlite3`. يمكن نسخ جميع البيانات من زر «نسخة من بياناتي» واستعادتها من نافذة الاستيراد.

## طريقة الاستخدام

1. اضبط «ثوابت التعبئة» مرة واحدة: المنطقة، الدائرة، الأسماء، الوقت والملاحظات المعتادة. التغيير يسري على الأوامر الجديدة.
2. أضف أمرًا أو حمّل قالب الاستيراد. يدعم `.xlsx` وCSV وجدولًا ملصقًا بعناوين الأعمدة. اجعل أرقام المغذيات والاشتراكات التي تبدأ بصفر نصوصًا في Excel.
3. راجع الأعمال المنفذة؛ الربط الابتدائي: 801 عدادات، 402 عدادات وحفر، 409 حفر ووصلات، 404 حفر ونهايات ومحول ووحدة حلقية وتأريض. يمكن تعديل الاختيار لكل أمر.
4. اضغط «أكمل الناقص». يُسأل عن الحقول الناقصة فقط. «أتركها فارغة» يسجل القرار ولا يكرر السؤال. لا يطلب تاريخَي إجراء 190 و200 ولا يكتبهما على النسخ الجديدة. لا يخمّن بيانات CT أو سنوات العدادات المختصرة.
5. عدّل التقييمات من تبويب الفحص. «الكل نعم» و«الكل لا ينطبق» أفعال صريحة منك؛ حفظ كنمط يجعل الإجابات نمطًا للأوامر الجديدة فقط. بند المخلفات في التفتيش مصاغ سلبًا: نعم تعني وجود مخلفات. بند تلف قاعدة الوحدة في SEC-09: نعم تعني وجود تلف.
6. راجع المعاينة، ثم صدّر PDF أو حدّد مجموعة لتحميل ZIP. يشغّل الخادم التصدير في الخلفية مع بيان عدد الأوامر المكتملة، ويدعم حتى 100 أمر في الدفعة. نموذج 200 يُقسّم إلى صفحات عند تجاوز 10 عدادات.

النماذج الأساسية: تسليم، تفتيش، ميداني، يومية الاستشاري، يومية المقاول، متابعة مخالفات. تضاف نماذج الأعمال وفق الاختيار. وضع «تفتيش الموقع فقط» يولد صفحة التفتيش وحدها.

جهد المنخفض متغير لكل أمر عمل: اختر 230 أو 400 فولت من بيانات الأمر أو تبويب العدادات. تستخدم خانات الجهد في نموذج 200 جهد الأمر، ويمكن تحديد استثناء لعداد بعينه. لا يفترض البرنامج 400 عند غياب البيانات؛ يظهر سؤال الجهد ضمن النواقص، وتركه فارغًا يبقيه فارغًا في PDF. يدعم جدول الاستيراد عمود «الجهد». جهد المتوسط بالكيلو فولت مستقل عن هذا الاختيار.

يضاف نموذج LV في نهاية كل حزمة أمر عمل تلقائيًا، ويكتب اسم ممثل المقاول في خانة Name & ID أسفل اليسار. البنود 5 و6 عليها صح دائمًا؛ مع تركيب عداد تضاف 11 و12 و13 و14، ومع لوحة توزيع «بيلر» تضاف 7 و8 و9 و10. عند اجتماع العملين تجمع العلامات، وتبقى الخانات الأخرى فارغة. تحسب العلامات عند المعاينة والتصدير للأوامر الحالية والجديدة، ولا تطلب أسئلة إضافية أو تعتمد على نمط LV قديم. لا يظهر LV ضمن اختيار الأعمال أو خانات الفحص؛ يبقى متاحًا في قائمة النماذج للمعاينة والتصدير.

## إدارة النماذج

القسم موجود تحت «ثوابت التعبئة» ويدير النماذج المدعومة في الحزمة. اختر نموذجًا وحدد قاعدة ظهوره: دائمًا، عند وجود أي من أنواع العمل المختارة، أو لا يظهر. يبقى وضع «تفتيش الموقع فقط» مخصصًا لصفحة التفتيش وحدها.

اضغط خانة فوق معاينة النموذج أو اخترها من القائمة. يمكن تحريكها بالسحب أو بالأرقام، وتغيير مساحة النص من زاوية المربع وحجم الخط من الخصائص. محتوى النص يمكن أن يأتي من الأمر، أو يكون ثابتًا، أو يترك فارغًا. ويمكن إضافة نص ثابت في مكان جديد. بنود الفحص تقبل تقييم الأمر، أو تقييمًا ثابتًا، أو تقييمًا يظهر مع أنواع عمل محددة، أو فراغًا. تبقى بنود CT والعداد المؤقت مرتبطة بوجودها في العمل.

«بيانات المعاينة» تسمح بتجربة النموذج على بيانات مثال أو أمر محفوظ دون تغيير الأمر. «حفظ كل التعديلات» يحفظ التعديلات لكل النماذج التي عدلتها في هذه الجلسة. الإعدادات مشتركة بين الأجهزة وتطبق على الأوامر الحالية والجديدة عند المعاينة والتصدير؛ لا تعيد كتابة بيانات الأوامر، ولا تعدل ملفات PDF الأصلية أو توقيعاتها. «إرجاع إعدادات هذا النموذج» أو إرجاع خانة واحدة يعيد الوضع المعتمد بعد الحفظ. تستثنى النماذج المخفية والبنود المثبتة من أسئلة النواقص ذات الصلة.

حجم الخط مقيد بمساحة الخانة لتجنب التداخل؛ وسع المربع إذا احتاج النص مساحة أكبر. تطبق خانات جدول 200 على مواضع الصفوف العشرة نفسها في كل صفحة إضافية. تشمل النسخ الاحتياطية وحزمة نقل الموقع إعدادات إدارة النماذج.

«إضافة خانة للتعبئة» تنشئ خانة باسم تختاره ومكان تحدده على النموذج. اختر نصًا أو أرقامًا أو تاريخًا، وحدد هل تطلب ضمن النواقص. تعبأ القيم داخل تبويب «خاناتي» لكل أمر على حدة؛ لا تكتب قيم المعاينة في بيانات الأمر. تظهر الخانات فقط مع النماذج الموجودة في حزمة الأمر، وتحفظ أرقامها كنص للحفاظ على الأصفار في البداية. إخفاء الخانة أو حذف تعريفها لا يمسح قيمها القديمة من الأوامر، ونسخ الأمر لمسودة جديدة يفرغ قيم الخانات الإضافية.

خط الواجهة أكبر مع مسافات وتباين أوضح. خيار «حجم الخط» أعلى الموقع يتيح 16 أو 18 أو 20 ويحفظ تفضيل القراءة على الجهاز؛ خط PDF وتخطيط أصول النماذج مستقلان عنه.

**حدود الإصدار:** استيراد البيانات من جداول، وليس استخراجًا تلقائيًا من صور أو ملفات ممسوحة. التقييمات غير المحفوظة تحتاج إجابة أو قرار تركها فارغة. الأسماء والتوقيعات المدمجة في ملفات الأصل لا تُمسح. راجع PDF قبل اعتماده، خاصة النصوص الطويلة والنماذج الفنية التي تتغير بياناتها.

## التشغيل من أكثر من جهاز

المشروع جاهز للتشغيل على خادم Docker، لكنه لم يُنشر على الإنترنت تلقائيًا. GitHub يحفظ الشيفرة؛ GitHub Pages وحده لا يشغّل توليد PDF وحفظ SQLite.

```bash
APP_PASSWORD='choose-a-password' docker compose up --build -d
```

للاستخدام عبر الإنترنت، شغله خلف HTTPS ومرر `APP_PASSWORD` كمتغير بيئة. اسم المستخدم في تسجيل الدخول يمكن أن يكون أي اسم؛ تتحقق الخدمة من كلمة المرور. احفظ قرص `/data` بشكل دائم مع النسخ الاحتياطي. تتشارك الأجهزة المتصلة بالخادم نفسه الأوامر المحفوظة؛ لا توجد إدارة حسابات متعددة في هذا الإصدار.

متغيرات التشغيل: `HOST` (افتراضيًا 127.0.0.1)، `PORT` (8080)، `DATA_DIR`، `APP_PASSWORD`.

## Render Free + Neon Free: موقع واحد ببيانات مشتركة

الإعداد الحالي في `render.yaml` يستخدم **خدمة Render Free دون أي قرص مدفوع**. تخزن الأوامر والثوابت والنماذج الخاصة في PostgreSQL على Neon؛ ملفات الخادم المؤقتة تستخدم كذاكرة تخزين فقط، ولا يعتمد بقاء البيانات عليها. راجع دائمًا أن الخطة المعروضة في الحسابين Free قبل التأكيد.

1. أنشئ حسابًا ومشروعًا مجانيًا في https://console.neon.tech . من Connect انسخ **Connection string** الذي يبدأ بـ `postgresql://`؛ لا تنسخ أمر `psql` كاملًا. احتفظ بإعداد SSL الذي يضيفه Neon.
2. افتح https://dashboard.render.com/blueprint/new?repo=https://github.com/kores20/kores20 واربط المستودع. ألصق رابط قاعدة البيانات في متغير `DATABASE_URL` على Render نفسه، ولا تضعه في الكود أو الدردشة.
3. تأكد أن الخدمة Free ولا يوجد Disk، ثم انشرها. يولّد Render قيمة `APP_PASSWORD`؛ أظهرها من Environment وافتح رابط الموقع HTTPS بأي اسم مستخدم وهذه الكلمة.
4. من نسختك الحالية افتح «نقل الموقع» ثم «تحميل حزمة النقل». ارفع الملف نفسه في «نقل الموقع» على موقع Render. الحزمة الخاصة تضم الأوامر والثوابت والنماذج؛ لا تنشرها على GitHub.
5. استخدم رابط Render نفسه على كل جهاز. الأوامر محفوظة في قاعدة واحدة، وتظهر التعديلات على الجهاز الآخر بعد تحديث الصفحة. هذه ليست مزامنة نسخ محلية منفصلة.

الخدمات المجانية قد تدخل في وضع الخمول، لذلك قد يتأخر أول فتح. تظل البيانات في قاعدة Neon عند إعادة تشغيل Render أو إعادة نشره، وتُحمّل ملفات PDF الخاصة من القاعدة تلقائيًا عند الحاجة. حافظ على النسخ الاحتياطية وراجع حدود وسياسات الخطط المجانية في حسابيك؛ ليست هذه ضمانة استضافة أو توفر دائم.

متغيرات السحابة: `DATABASE_URL`, `APP_PASSWORD`, `HOST=0.0.0.0`, `DATA_DIR=/tmp/namothaj`, `TEMPLATE_DIR=/tmp/namothaj/templates`. يرفض التطبيق البدء على Render دون قاعدة خارجية وكلمة مرور. محليًا، غياب `DATABASE_URL` يبقي SQLite وملفات النماذج على الجهاز كالمعتاد.

يمكن استعادة حزمة النقل على موقع فارغ فقط حتى لا تستبدل بيانات أحدث بنسخة قديمة. تحديثات الكود تأتي من `main`، وبيانات الأوامر والنماذج الخاصة خارج مستودع الكود.

## تحديث نسخة ويندوز

أغلق نافذة تشغيل الموقع وافتح `update-windows.bat`، ثم أعد فتح `run-windows.bat`. يحمّل التحديث الكود من الفرع `main` ويحافظ على `.data` و`.venv` وملفات النماذج الأصلية. ملفات الكود المستبدلة تحفظ قبل التغيير تحت `.updates`.

إذا كان المستودع خاصًا، يمكن تنزيل Code → Download ZIP من GitHub وتشغيل `.venv\Scripts\python.exe update_local.py --archive "path-to-zip"`، أو استخدام متغير `GITHUB_TOKEN` على الجهاز نفسه. لا تضع الرمز في الشيفرة أو في الدردشة.

## التحقق

```bash
python -m unittest discover -s tests -v
```

لتشغيل اختبار المتصفح الاختياري: `pip install playwright` ثم `playwright install chromium` و`python tests/browser_smoke.py`. يمكن تحديد `CHROMIUM_PATH` عند وجود متصفح مثبت مسبقًا.

الخط Haya مرفق مع ملف الترخيص الذي قدمه المستخدم في `app/assets/font-license.txt`. ملفات النماذج هي النسخ التي قدمها المستخدم.
